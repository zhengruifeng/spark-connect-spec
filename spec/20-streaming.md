# 20. Streaming

*Reserved for a future version of this specification.*\
This chapter will define the Structured Streaming surface: `WriteStreamOperationStart`, `StreamingQueryCommand`, `StreamingQueryManagerCommand`, `StreamingQueryListenerBusCommand`, watermark and event-time semantics (`WithWatermark`), output modes (Append / Complete / Update), source and sink connectors, checkpointing, stateful operators (`ApplyInPandasWithState`, `TransformWithState`), and streaming-query progress reporting (`StreamingQueryProgress`).\
Streaming is deferred from v1.0. Unlike UDFs (a delegate-to-subprocess problem), streaming is an implement-a-subsystem problem: a conforming server has to gain a streaming runtime — micro-batch scheduling, state store, watermark algebra, checkpoint format — woven into its query execution layer. The implementation work is substantially larger than UDFs, and checkpoint-format compatibility imposes a hard cross-engine portability limit (queries with different checkpoint formats cannot resume across engines).\
A v1.0-conforming server MAY implement streaming ahead of the spec. Such behavior is outside SC-1.0-P1; v1.0 fixes only the pinned IDL wire shape and makes no portable scheduling, state-store, checkpoint, progress, recovery, or future-compatibility claim for the implementation. The streaming-related proto messages (`WriteStreamOperationStart`, `StreamingQueryCommand`, `StreamingQueryManagerCommand`, `StreamingQueryListenerBusCommand`, `WithWatermark`, `ApplyInPandasWithState`) and the `Relation.read` with streaming formats are not part of the v1.0 conformance surface.\
Spark Declarative Pipelines (SDP), which sit on top of Streaming, are likewise deferred — they follow Streaming in the phasing plan. `Command.pipeline_command` is not part of the v1.0 conformance surface.\
